V11 Scope Reset

Voice-to-Action Agent

一个聚焦具身智能交互的产品原型：用户说一句自然语言任务，系统完成意图理解、对象定位、安全确认、动作规划、执行反馈和异常恢复。

打开主 Demo 核心验收

Product Promise

从一句话到一个可执行的机器人任务流

这个项目不再主打“作品集材料很多”，而是收缩为一个清晰产品：把模糊语音/文本指令变成安全、可解释、可观察的物理世界任务执行过程。

Understand识别用户想做什么，是搬运、递送、检查还是机器人自主导航。
Ground把“杯子”“老人旁边那个东西”“这个”映射到场景对象。
Act Safely对药盒、老人、重物、门口等高风险任务做确认和兜底。
一句话讲法：
Voice-to-Action Agent 验证的是具身智能产品的核心链路：自然语言不是答案生成，而是任务执行入口。系统必须先理解、定位、确认风险，再规划动作并反馈执行状态。

Core Flow

主流程只保留 6 步

后续优化都围绕这条链路展开，其他材料和实验页不再作为主产品入口。

1. 用户输入任务 2. Intent 识别 3. Object Grounding 4. Safety Gate 5. Route / Action Plan 6. Execute / Recover

Focused Scope

保留的核心能力

自然语言任务理解

支持文本和浏览器语音输入，把“把红色杯子拿到厨房台面”等自然语言变成结构化任务。

指代和对象澄清

处理颜色、位置、旁边、当前选中对象等 grounding 线索；对象不唯一时先澄清。

安全确认和接管

药盒、老人照护、重物、门口等任务不直接执行，必须进入确认或人工接管路径。

物理执行可视化

展示机器人移动、携带物体、路线预览、执行时间线和异常恢复，而不是只输出文本解释。

Demo Script

建议只演示 4 条路径

日常执行

把桌上的红色杯子拿到厨房台面

证明从自然语言到可执行任务流的基础闭环。

歧义澄清

把杯子拿到厨房

证明系统不会擅自选择对象，而会向用户确认红色还是蓝色。

安全确认

把药盒递给老人

证明高风险物理任务不会因为理解正确就直接执行。

执行中改口

别放厨房了，放门口

证明机器人任务执行过程中仍能处理用户意图变化。
