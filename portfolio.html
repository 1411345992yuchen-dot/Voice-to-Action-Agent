Problem

为什么不是再做一个语音助手

具身智能机器人进入真实场景后，用户不会只给标准命令。更常见的是“右边那个杯子”“老人旁边那个东西”“先别撞到椅子”。这些指令同时包含意图、对象、空间关系、安全约束和上下文。

因此产品问题不是“机器人能不能聊天”，而是“机器人能否把模糊语言转成安全可执行的物理任务，并在失败时可控地恢复”。

Solution

用多 Agent 拆解具身交互任务

01

Intent Agent

识别检查、递送、搬运、拿取放置等任务意图。

02

Grounding Agent

将“这个”“右边那个”“老人旁边”映射到场景对象。

03

Safety Agent

识别药品、重物、门口、老人等高风险上下文。

04

Recovery Agent

预测路径阻塞、敏感递送、避障失败，并给恢复策略。

05

Planner Agent

把用户意图转成导航、拿取、放置、路线策略和反馈序列。

06

Interruption Agent

执行中识别暂停、改目标、换对象和人工接管。

07

Evaluator Agent

输出执行置信度，并通过评估集做行为回归。

Career Narrative

这件作品怎么服务转型

这个项目将 AI 工程、多 Agent 工作流、语音交互、车辆/机器人背景连接成一条产品叙事：我关注的不是普通聊天助手，而是自然语言如何成为具身智能任务入口。

它可以支撑“语音/多模态 Agent 产品经理 -> 机器人交互产品经理 -> 具身智能产品经理”的转型路径，并展示任务流设计、安全边界、失败态、动态改口和评估意识。
