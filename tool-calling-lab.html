Architecture Thesis

先固定工具契约，再替换模型能力

真实 Agent 产品不能把所有判断都塞进一段 prompt。V9.2 的重点是建立稳定工具契约：LLM 可以负责选择工具和组织计划，但物理执行前必须经过 grounding、安全门控、路线规划和评估检查。

Contract每个工具都有输入、输出和失败边界。
Gate澄清、确认、阻止执行都是显式工具结果。
Swap后续可把 mock planner 替换成真实 LLM。
面试讲法：
我没有直接说“接入 LLM 就行”，而是先定义工具调用边界。LLM 只负责把用户输入组织成可审计的工具调用链，最终执行仍由 grounding、安全、路线和门控模块约束。这更接近真实 Agent 产品的工程化落地方式。
