V8.1 Demo Runbook

现场演示 Runbook

这页是为了防止面试现场“想演但顺序乱”：按步骤打开、输入、观察、解释，出问题也有备用路线。

Live Sequence

推荐现场演示顺序

Step 1

打开作品集首页

入口：/portfolio-hub.html。先讲一句话定位，不急着进入技术细节。

观察点：面试官先知道这是 Agent / 语音 / 具身智能 PM 转型项目。

Step 2

进入面试演示模式

入口：/interview-demo.html。展示四条黄金路径：日常递送、歧义澄清、老人药品确认、执行中改口。

观察点：项目不是只会跑单一路径，而是覆盖真实语音任务中的复杂情况。

Step 3

跑主 Demo

输入：把红色杯子拿到厨房台面。观察对象识别、路线生成、机器人移动、物体随行和任务状态。

观察点：自然语言被拆成对象、目标、路径、执行状态，而不是直接变成聊天回复。

Step 4

打开 Agent 架构

入口：/agent-architecture.html。解释每个模块输入、输出、失败风险和指标。

观察点：技术可信度来自模块边界和质量归因，不是堆 Agent 名词。

Step 5

打开测试计划

入口：/test-plan.html。讲 expected vs actual、PM Review、Review Sandbox。

观察点：你有产品质量意识，知道如何验证 Agent 行为稳定性。

Fallback

现场兜底方案

如果主 Demo 没来得及跑

直接打开 `interview-demo.html` 和 `evidence-dashboard.html`，用静态证据讲清四条路径和质量闭环。

如果被追问技术实现

打开 `agent-architecture.html`，按输入、输出、失败风险、指标解释模块，不陷入代码细节。

如果被问真实机器人差距

回答：当前是产品链路 MVP，下一步是 ASR、LLM function calling、VLM grounding 和机器人 SDK 接入。

如果被问为什么不是纯 PM 文档

强调你既能定义产品问题，也能落地可运行原型和评估集，这是技术 PM 的优势。
