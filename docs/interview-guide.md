# Voice-to-Action Agent 面试讲解指南

## 30 秒版本

这是一个面向家庭 / 服务机器人的 Voice-to-Action Agent 原型，核心是把用户自然语言指令转化为安全可执行的机器人任务流。项目覆盖意图解析、场景对象 grounding、安全确认、路线规划、执行中改口、异常恢复和评估回归，目标是证明我具备从 AI 工程经验迁移到 Agent / 语音交互 / 具身智能产品经理的能力。

## 2 分钟版本

我做这个项目时没有一开始追求复杂模型，而是先验证具身交互产品的核心闭环：用户自然语言能否变成可执行任务。第一阶段解决对象指代和任务拆解，比如“右边那个杯子”“老人旁边那个东西”；第二阶段加入安全确认和异常恢复，比如药盒递送、重物搬运、路径被挡；第三阶段加入执行中打断和改口，比如“别放厨房了，放门口”；第四阶段补齐语音确认、短回复、机器人反馈话术和评估集；最后把项目包装成面试演示、证据卡、语音专项和 Agent 架构页。

它和我在华为做多 Agent 告警工作流的经验是连续的：本质上都是把人的模糊意图、SOP 或场景规则转化为可执行、可解释、可评估的工作流。区别是这个项目把能力迁移到了具身智能和语音交互场景。

## 建议演示顺序

1. 打开 `portfolio-hub.html`，用一句话讲项目定位。
2. 打开 `interview-demo.html`，展示四条黄金演示路径。
3. 选一条进入主 Demo，例如“把杯子拿到厨房”。
4. 打开 `voice-lab.html`，说明语音交互专项能力。
5. 打开 `agent-architecture.html`，解释多 Agent 架构。
6. 打开 `test-plan.html`，证明评估和质量治理。

## 面试官可能追问

### 这个项目为什么不用真实机器人？

当前阶段目标不是机器人控制，而是验证语音 / 多模态入口到具身任务执行的产品链路。用 2D 场景可以快速验证对象 grounding、安全门控、路线规划和异常恢复，后续再接 ROS / VLM / 真实设备。

### 这个项目和普通语音助手有什么不同？

普通语音助手主要回答问题或触发 App 功能；这个项目强调把语音意图转成物理世界任务，需要解决错拿、错送、高风险执行、路径阻塞和执行中改口等具身场景问题。

### 你在里面体现的产品经理能力是什么？

不是只写代码，而是定义了用户场景、任务边界、风险门控、评估指标、测试用例、面试演示路径和产品证据卡。它证明我能把复杂 Agent 系统拆成可交付、可验证、可讲述的产品方案。
