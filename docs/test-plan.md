# Test Plan Replay

## Purpose

V1.6 的目标是把“评估集通过”变成面试官可理解的产品质量治理页面。到 V2.7，测试计划页进一步纳入语音反馈、路径策略、路线重规划、路线质量评估、PM Review 复盘模式和 Review Sandbox 失败注入，说明：我知道哪些行为、话术和物理执行策略必须稳定，如何定义 expected，如何观察 actual，以及失败或高风险通过时如何复盘。

## Scope

- 基础评估：15 条，覆盖意图、对象 grounding、目标位置、安全确认和恢复预案。
- 打断评估：7 条，覆盖暂停、改目标、换对象、路线重规划、人工接管、改放安全区和无效打断。
- 语音评估：7 条，覆盖理解、澄清、安全确认、异常恢复、中途改口、路线重规划和人工接管话术。
- 路线评估：4 条，覆盖 direct / avoid_chair / navigation / elder handoff 的路径分段、风险标记、策略标签和路线评分。
- 总计：33 条可回放用例。
- PM Review：覆盖产品定义、Grounding、安全门控、路线规划、路线评分、执行状态机和话术策略归因。
- Review Sandbox：支持模拟错拿对象、路线低分、安全漏检和旧任务泄漏，真实基线仍保持 100%。

## Interview Narrative

这部分可以这样讲：

> 我没有只做一个看起来能跑的原型，而是把 Agent 行为、语音反馈和路线质量都拆成可回归的测试用例。基础评估验证机器人能不能理解和规划，打断评估验证用户中途改变意图时系统是否能安全取消旧动作、保留上下文并重建任务，语音评估验证关键状态是否说对话，路线评估验证路径分段、绕行点、风险标记和路线评分是否符合物理执行预期。测试计划页把 expected 和 actual 展开，并用 PM Review 自动归因到产品定义、Grounding、安全门控、路线规划、路线评分、执行状态机或话术策略。V2.7 再加入 Review Sandbox，让我可以主动演示一个事故如何被定位、分级并转成下一步产品动作。
## V3.4 Scope Addendum

- 当前测试计划真实回归基线为 37 条：基础 15 条、打断 7 条、语音 7 条、路线 4 条、高级交互 4 条。
- 高级交互覆盖：多轮澄清、多轮确认、顺序任务队列、执行中动态感知。
- 每条 case 详情新增 `PM Demo Guide`，把测试结果翻译成面试讲解资产：产品问题、观察证据、决策口径、下一步指标、60 秒讲解词。
- 新增筛选项：全部 / 基础 / 打断 / 语音 / 路线 / 高级 / 沙盒。

## V3.5 Main Demo Linkage

- 主 Demo 的 `Quality Evidence / PM 讲解` 面板会读取测试计划数据。
- 当前任务如果命中评测用例，会显示匹配用例和“已纳入回归”。
- 当前任务如果没有精确命中，会显示“建议补充用例”，用于发现下一批评测样本。
- 这让测试计划不再只是独立页面，而是成为现场 Demo 的证据层。
