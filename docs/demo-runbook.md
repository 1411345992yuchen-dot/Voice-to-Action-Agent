# Demo Runbook

## Goal

Give a reliable sequence for live interviews so the project can be demonstrated without improvising the order.

## Sequence

1. Open `portfolio-hub.html`.
   - Explain the one-line positioning.
   - Do not start with implementation details.

2. Open `interview-demo.html`.
   - Show daily delivery, ambiguity clarification, elder medicine confirmation, and mid-execution correction.

3. Open `index.html`.
   - Run: 把红色杯子拿到厨房台面
   - Point out object grounding, route generation, robot movement, carried object behavior, and task status.

4. Open `agent-architecture.html`.
   - Explain Intent, Grounding, Safety, Planner, Execution / Interruption, and Evaluator.

5. Open `test-plan.html`.
   - Explain expected-vs-actual, PM Review, and Review Sandbox.

## Fallbacks

- If there is no time for the live demo, show `interview-demo.html` and `evidence-dashboard.html`.
- If the interviewer asks about real robot gaps, explain that the current MVP validates product flow first; the next stage is ASR, LLM function calling, VLM grounding, and robot SDK integration.
- If the interviewer asks why this is not only a coding project, emphasize product decisions, risk gates, evaluation sets, and role-specific storytelling.
