# Interview Q&A

## 1. 这个项目解决什么问题？

它解决的是具身智能交互里的“自然语言到物理任务执行”问题。用户不会总是给标准指令，常常会说“右边那个杯子”“把这个拿到厨房”“小心别撞椅子”。这个项目验证机器人如何把这些模糊指令拆成意图、对象、位置、风险、计划和恢复策略。

## 2. 为什么不用普通语音助手来讲？

普通语音助手重点是回答问题或完成数字任务；具身智能交互重点是让物理机器人安全执行动作。这里必须处理对象 grounding、安全确认、执行状态、失败恢复和人工接管，所以我把项目定位成 Voice-to-Action，而不是 Chat-to-Answer。

## 3. 你的产品设计亮点是什么？

- 用多 Agent 拆解任务链路：Intent、Grounding、Safety、Recovery、Planner、Evaluator。
- 支持“这个”“右边那个”“老人旁边那个”等多模态指代。
- 高风险任务不会直接执行，会进入安全确认或人工接管。
- 对门口阻塞、药品递送、避障等失败态预置恢复策略。
- 支持执行中用户打断和改口，能暂停、改目标、换对象或人工接管。
- 补齐机器人输出侧语音反馈，覆盖理解、确认、执行、恢复和接管。
- 将低风险任务、歧义澄清、安全确认、异常恢复、中途改口和人工接管沉淀成语音交互脚本。
- 新增 Grounding 证据、路径预览、路线重规划和路线质量评估：用户能看到为什么选中某个对象、机器人会怎么走，“绕开椅子走”是否真的改变路线，以及路线报告是否符合验收标准。
- 用评估集做行为回归，当前基础评估 15/15、打断专项评估 7/7、语音反馈评估 7/7、路线质量评估 4/4 通过，并通过测试计划页展示 expected vs actual。

## 4. 这个项目和你的经历怎么连接？

我当前在华为做多 Agent 协同和零代码告警定界程序生成，本质上是在把专家意图转成可执行工作流。这个项目把同样的能力迁移到具身智能场景：把用户自然语言意图转成机器人可执行任务流。我的小米智能座舱语音、小爱连续对话和美团外呼经历，也能支撑语音交互和多轮策略设计。

## 5. 你为什么选择规则型 Agent，而不是直接接大模型？

第一阶段目标是验证产品结构，而不是追求模型效果。规则型实现更稳定、更可解释，也方便展示每个 Agent 的职责。后续可以把 Intent、Grounding、Planner 替换成 LLM function calling 或 VLM grounding，但产品链路会保持一致。

## 6. 如果继续做，你会怎么迭代？

优先做三件事：

1. 把路径评估进一步量化，例如绕行成功率、风险区域停留时长、任务完成耗时和用户二次打断率。
2. 接入真实 LLM/VLM，让 grounding 和规划从规则升级为模型能力。
3. 用更真实的场景图或仿真环境替代当前 2D 场景，并逐步接近 ROS/机器人仿真。

## 7. 这个项目体现了哪些 PM 能力？

- 从目标岗位反推作品集主题。
- 把复杂技术拆成可解释产品模块。
- 设计高风险场景的人机协同边界。
- 关注失败态、动态改口、恢复策略、路线质量和可回归评估。
- 用 Demo、PRD、指标、架构和演示脚本构成完整产品叙事。
