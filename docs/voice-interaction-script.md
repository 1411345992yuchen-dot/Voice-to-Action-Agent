# Voice Interaction Script

## Purpose

V1.9 将 V1.8 的“机器人语音反馈”沉淀为可展示、可复盘、可面试讲解的对话设计资产。它不是单纯把文字读出来，而是定义每个系统状态下机器人应该说什么、为什么这么说、如何降低用户风险，以及用什么指标验证。

## Product Positioning

Voice-to-Action Agent 的语音体验分成两层：

- 输入层：用户用自然语言表达任务、修正任务或接管任务。
- 输出层：机器人用状态反馈建立信任，让用户知道系统听懂了什么、正在做什么、哪里需要确认，以及异常时怎么恢复。

这更接近具身智能交互 PM 的工作，而不是传统语音助手的闲聊设计。

## Script Principles

| Principle | Meaning |
|---|---|
| 先复述结果，不复述过程 | 用户需要知道系统理解成了什么任务，而不是听内部解析流程。 |
| 风险场景必须显式确认 | 药品、老人、重物、门口等场景不默认自动执行。 |
| 执行状态要可预期 | 开始、前往、放置、完成、暂停都要有短反馈。 |
| 失败态给选择，不甩锅 | 异常恢复时提供重规划、换目标、等待或接管等可行动选项。 |

## Core Scripts

| Scenario | User Utterance | Robot Feedback | PM Rationale |
|---|---|---|---|
| 低风险任务 | 把红色杯子拿到厨房台面 | 我已理解任务，目标位置是厨房台面。现在开始执行。 | 低风险任务不打断用户，只给开始和完成反馈。 |
| 歧义澄清 | 把杯子拿到厨房台面 | 我需要确认目标对象。请在候选项里选择你指的是哪一个。 | 多候选对象不猜测，避免拿错真实物体。 |
| 安全确认 | 把药盒递给老人 | 这是高风险任务。我需要你确认后再执行，也可以转人工接管。 | 将安全边界显式产品化。 |
| 异常恢复 | 把重箱子搬到门口 | 检测到通道可能受阻，请从恢复选项中选择下一步。 | 异常发生时让用户恢复控制权。 |
| 中途改口 | 别放厨房了，放门口 | 用户改口更换目标位置：门口。我会取消旧动作，并按新的任务计划继续。 | 承认最新意图，并说明旧动作会被取消。 |
| 人工接管 | 交给我，我来接管 | 我已安全停止，并保留任务上下文供人工接管。 | 把接管设计为安全出口，而不是失败。 |

## State to Metric Mapping

| State | User Risk | Feedback Strategy | Metric |
|---|---|---|---|
| Understanding | 不知道机器人是否听懂 | 说明正在解析对象、位置和安全条件 | 理解反馈触达率 |
| Clarification | 拿错对象 | 要求用户确认候选对象 | 澄清成功率 |
| Safety Confirmation | 危险任务被误执行 | 说明风险并提供确认或接管 | 高风险确认率 |
| Recovery | 机器人卡住或行为异常 | 给出可选恢复策略 | 异常恢复率 |
| Interruption | 旧动作继续执行 | 确认新意图并说明取消旧动作 | 改口处理成功率 |

## Interview Narrative

可以这样讲：

> 我不是只做了一个播报开关，而是把具身任务流里的语音输出拆成状态反馈系统。每一句话术都对应一个系统状态和用户风险：理解、澄清、确认、执行、恢复、打断、接管。这样设计的核心价值是建立用户对机器人的可控感和信任感，也让语音 Agent PM 的工作从“写提示语”升级为“设计任务状态与人机协作边界”。
