# Failure Recovery

## Why It Matters

真实机器人产品不能只覆盖理想路径。具身智能系统会遇到路径阻塞、抓取失败、对象歧义、用户改口、敏感物品递送等失败态。产品经理必须设计“失败后怎么办”和“用户中途改变主意怎么办”，而不是只追求一次性自动完成。

## V1.3 Recovery Agent

Recovery Agent 在任务执行前预测可能中断，并在执行中模拟暂停：

- `blocked_path`: 重箱子搬到门口，门口通道可能狭窄或被占用。
- `sensitive_handoff`: 药品递给老人，需要更严格确认。
- `obstacle_avoidance`: 用户提到椅子、障碍或小心执行。

## Recovery Options

| Option | 使用场景 | 产品意义 |
|---|---|---|
| 重规划路径 | 门口通道或障碍物风险 | 保持自动化，但降低误执行 |
| 改目标位置 | 原目标不安全或不可达 | 允许用户快速修改任务 |
| 暂停等待 | 用户可清理障碍 | 让机器人等待人类介入 |
| 人工接管 | 高风险或不确定场景 | 优先安全和责任边界 |

## PM Interview Narrative

这部分展示的不是算法炫技，而是产品安全边界：机器人必须知道什么时候继续、什么时候停、什么时候问用户、什么时候交给人。具身智能 PM 的价值之一，就是把这些失败态设计成清晰、可解释、可恢复的交互。
