# Route Quality Evaluation

## Purpose

V2.5 的目标是把“机器人会怎么走”从视觉展示升级为可验收、可评分、可对比的产品质量对象。路线不是画出来就算完成，还需要验证：

- 路线是否包含正确的起点、取物点、绕行点和终点。
- 用户要求绕开障碍时，路线是否真的加入绕行点。
- 路线报告是否识别到障碍、门口、老人交接和高风险物体等风险。
- 策略标签是否能解释为什么采用默认路径、主动绕行、低速避障或高风险确认。
- 路线评分是否能量化安全、效率、可行性和风险暴露。
- 默认路线和绕行路线是否能给出可解释的推荐理由。

## Data

```text

```

当前覆盖 4 条路线质量用例，并在每条用例中验证路线评分、评分等级和推荐路线：

- `route_direct_heavy_box_001`：重箱子搬到门口，验证默认路径、椅子接近风险、高风险物体和门口空间检查。
- `route_avoid_chair_heavy_box_001`：重箱子搬到门口并绕开椅子，验证主动绕行点、障碍已规避、低速避障和不再输出 near_chair。
- `route_navigation_living_room_001`：机器人移动到客厅，验证无物体导航也能生成路线报告，并保留障碍接近风险。
- `route_elder_medicine_handoff_001`：药盒递给老人，验证高风险物体、老人座位交接和靠近老人降速策略。

## Scoring Model

V2.5 新增路线评分卡：

- `安全分`：根据高风险、 medium 风险、低风险规避和绕行行为综合计算。
- `效率分`：根据路线总距离、分段数量和绕行成本计算。
- `可行性分`：根据目标点、执行段和高风险物体可操作性计算。
- `总分/等级`：以安全为最高权重，综合输出 A/B/C/D。
- `风险暴露`：把高风险、medium 风险和低风险规避点转换为一个可比较数字。
- `路线对比`：对门口/障碍相关任务展示默认路线和绕行路线，并给出推荐理由。

## What It Proves

路线质量评估证明这个原型不只做自然语言理解，还在做具身智能产品必须关心的物理执行治理：

- 物理路径可解释：用户能知道机器人从哪里走、经过哪里、为什么绕行。
- 路线选择可解释：用户能看到默认路线和绕行路线的安全、效率和风险暴露差异。
- 安全风险可复盘：风险不只停留在提示文案，而是进入评估集。
- 策略退化可发现：如果后续改代码导致绕行点丢失、风险标记缺失、评分异常或推荐路线错误，测试计划页会暴露失败。

## Interview Talk Track

可以这样讲：

> 我把路线规划从 Demo 效果升级成了可验收对象。V2.2 先让用户看见机器人会怎么走，V2.3 让用户中途说“绕开椅子走”时路线真的改变，V2.4 把路线分段、绕行点、风险标记和策略标签写进评估集，V2.5 再进一步把路线变成可评分、可对比、可推荐的产品决策。这样我不仅能展示一个能跑的原型，也能说明我会定义具身智能产品中的执行质量标准。
