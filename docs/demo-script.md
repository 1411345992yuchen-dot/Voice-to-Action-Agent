# Demo Script

## 30-second Opening

这个项目是一个面向具身智能交互的 Voice-to-Action Agent 原型。它不做普通聊天，而是验证机器人如何把用户自然语言指令转成可执行、安全、可评估的任务流。

## Demo Flow

1. 打开本地页面：

```text
http://localhost:8765
```

2. 点击示例：“把桌上的红色杯子拿到厨房台面”。

讲解点：

- Intent Agent 识别为拿取放置任务。
- Grounding Agent 定位红色杯子和厨房台面。
- Safety Agent 判断低风险，可自动执行。
- Planner Agent 生成技能序列。
- 场景中机器人移动并反馈任务状态。

3. 点击示例：“把药盒递给老人，但先确认是不是蓝色那个”。

讲解点：

- 药盒和老人场景触发高风险门控。
- 系统不会直接执行，需要用户确认或人工接管。
- 这体现具身智能产品必须处理安全边界，而不只是追求自动化。

4. 点击“运行评估集”。

讲解点：

- 评估集用于验证 Agent 行为稳定性。
- 当前评估集 15/15 通过。
- 这展示了产品经理对 Agent 行为质量和回归测试的意识。

4.1 点击“运行打断评估”。

讲解点：

- 这不是普通单次 demo，而是对动态意图变化的专项回归。
- 当前打断评估覆盖暂停、改目标、换对象、路线重规划、人工接管、改放安全区和无效打断，7/7 通过。
- 这体现产品经理不仅设计交互，还定义可持续验证行为质量的方法。

4.2 点击“运行语音反馈评估”。

讲解点：

- 这一步验证机器人是否在正确状态触发正确话术。
- 当前语音评估覆盖理解、澄清、安全确认、异常恢复、中途改口、路线重规划和人工接管，7/7 通过。
- 这体现语音 Agent PM 不只设计脚本，还会把脚本纳入回归治理。

4.3 点击“运行路线质量评估”。

讲解点：

- 这一步验证机器人生成的路线报告是否可验收，而不只是画出一条线。
- 当前路线评估覆盖直达搬运、绕开椅子、无物体导航和老人座位递送，4/4 通过。
- 这体现具身智能 PM 需要把物理执行质量拆成路径分段、绕行点、风险标记和策略标签。

4.4 打开测试计划页：

```text
http://localhost:8765/test-plan.html
```

讲解点：

- 这里把基础评估、打断评估、语音评估和路线评估合并成 33 条可回放测试用例。
- 每条用例都有 expected、actual、PASS/FAIL 和 PM 复盘口径。
- 这页适合向面试官展示：我能把 Agent 产品做成可治理、可复盘、可迭代的系统。

4.5 打开版本演进页：

```text
http://localhost:8765/version-history.html
```

讲解点：

- 这页适合用作项目开场。
- 从 V1.0 到 V2.4，每个版本都对应一个产品问题，而不是随便堆功能。
- 这能展示你的产品路线规划能力和转型叙事表达能力。

4.6 打开语音交互脚本页：

```text
http://localhost:8765/voice-script.html
```

讲解点：

- 这页把 V1.8 的语音反馈沉淀成对话设计资产。
- 每个场景都展示用户话术、机器人反馈、PM 设计意图和可打开的 Demo。
- 这能展示你不是只会做语音播报，而是会设计任务状态、风险表达和人机协作边界。

5. 点击场景里的蓝色杯子，再点击“把这个拿到厨房台面”。

讲解点：

- Grounding Agent 使用当前选中对象作为“这个”的上下文。
- 这模拟了具身智能中的多模态指代：用户可能指着/看着/点选某个物体，然后用语言补充动作。
- 这一步比传统语音助手更接近机器人交互。

6. 打开恢复演示：

```text
http://localhost:8765/?confirm=1&demo=把重箱子搬到门口
```

讲解点：

- Recovery Agent 预测门口通道阻塞风险。
- 执行中系统暂停，不会硬闯物理环境。
- 用户可以选择重规划路径、改放客厅安全区或人工接管。
- 这体现具身智能产品经理必须设计失败态，而不是只设计理想路径。

6.1 展示机器人语音反馈。

讲解点：

- 左侧“机器人语音反馈”区域会记录理解、确认、执行、恢复和打断话术。
- 打开“播报”后，浏览器支持时会朗读关键状态。
- 这体现语音交互不只是输入识别，还包括状态反馈和用户信任建立。

7. 打开中途改口演示：

```text
http://localhost:8765/?demo=把红色杯子拿到厨房台面&interrupt=别放厨房了，放门口
```

讲解点：

- 用户在机器人执行中改变目标位置。
- Interruption Agent 取消未完成动作，保留目标对象，并重建任务计划。
- 这展示真实人机协作中的动态意图控制，而不是一次性命令执行。

## Interview Close

这个项目对应我的转型路线：从多 Agent 工作流工程经验，迁移到语音/多模态 Agent 产品，再进一步进入具身智能交互产品。核心能力不是单点模型能力，而是任务流设计、安全确认、动态改口、异常兜底、路线质量和指标评估。
