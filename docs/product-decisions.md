# 产品决策说明

## 决策 1：先做 2D 原型，而不是 3D 或真实机器人

目标是验证语音 / 多模态入口到具身任务执行的产品闭环，而不是证明机器人控制能力。2D 原型更适合快速迭代对象指代、安全确认、执行路径和异常恢复。

## 决策 2：先解决 Grounding，再扩展更多场景

具身任务的核心风险不是“不会回答”，而是“错拿、错送、错执行”。因此优先支持“右边那个杯子”“老人旁边那个东西”“这个”等场景指代。

## 决策 3：高风险任务必须有确认或接管

药品递送、老人照护、重物搬运等任务不应该默认全自动执行。安全门控能体现产品边界，也能降低真实物理动作带来的风险。

## 决策 4：评估集是作品集证据，不是工程附属品

项目建立核心任务、执行中打断、语音反馈、路线质量和高级交互等评估集，用 expected vs actual 固定行为质量。这证明 PM 不只关心功能，也关心稳定性和可回归。

## 决策 5：语音识别结果先确认，再执行

物理世界任务的误触发成本高于普通聊天误答。语音识别进入可编辑确认区，可以平衡执行效率和安全信任。

## 决策 6：从功能 Demo 升级为作品集系统

V5-V6 不再继续堆功能，而是新增面试演示、岗位讲法、证据总览、决策日志和投递文档，让项目从“我做过”变成“我能讲清楚为什么这样做”。
