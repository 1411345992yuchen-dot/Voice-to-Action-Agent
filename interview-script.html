Talk Tracks

三套可直接使用的讲法

30 秒

快速定位

这是一个面向具身智能交互的 Voice-to-Action Agent 原型。我把用户自然语言任务拆成意图识别、对象 grounding、安全确认、路径规划、执行反馈和评估回归几个模块，用本地 Demo 验证“语音指令如何可靠地变成物理任务流”。它和我在华为做的多 Agent 告警工作流是连续的，都是把人的模糊意图转成可执行工作流。

3 分钟

标准项目介绍

我先定义了家庭机器人任务场景，不追求一开始接真实机器人，而是先验证产品闭环。第一步解决用户一句话任务的结构化理解，第二步解决“这个、旁边那个、老人旁边”这类对象 grounding，第三步补安全门控和人工接管，第四步做执行中改口和异常恢复，最后用评估集、测试计划和证据页证明行为稳定性。这个项目能体现我从工程实现转向产品定义的能力：不仅能做功能，也能定义边界、风险、指标和迭代顺序。

8 分钟

深挖讲法

先打开面试演示页讲四条黄金路径，再打开主 Demo 跑一个任务，接着打开 Agent 架构解释每个模块的输入输出和失败风险，最后打开测试计划说明 expected vs actual、PM Review 和 Review Sandbox。结尾讲下一步：接入真实 ASR / LLM function calling / VLM grounding / 机器人 SDK，把当前规则原型升级为更真实的具身交互系统。

Likely Questions

高频追问回答骨架

为什么不用 3D / ROS？

当前阶段目标是验证产品链路，不是验证机器人控制能力。2D 能更快暴露产品问题：对象指代、安全门控、异常恢复、执行状态和评估集。真实机器人控制是下一阶段，不应该抢走 MVP 的验证重心。

为什么规则实现，不直接上大模型？

规则实现让每个模块输入输出可解释，适合先做产品原型和测试集。后续可以把 Intent、Grounding、Planner 替换成 LLM function calling 或 VLM grounding，但产品边界和评估集先固定下来。

项目和华为经历有什么关系？

华为项目是把告警 SOP 转成多 Agent 工作流，这个项目是把家庭任务转成具身执行工作流。底层能力相同：任务抽象、流程编排、状态治理、异常兜底和质量评估。

你作为 PM 的贡献是什么？

不是只写代码。我定义了用户场景、任务边界、风险门控、评估集、版本路线、演示路径和岗位叙事，把一个功能原型沉淀成可投递、可追问的产品作品集。
