Voice PM Focus

语音 Agent 的关键不是多说话，而是降低误执行风险

家庭机器人语音交互最大的产品风险是误触发、过拒识、指代不清和执行中改口。V5.2 用状态机、短回复策略和指标表，把这些风险变成可设计、可验证的产品机制。

确认识别结果先进入可编辑确认区，不确定不直接执行。
补槽支持“红色的”“不是这个”“对”等短回复。
接管高风险和异常任务给出人工接管提示。

推荐面试讲法

我把语音交互拆成“识别可信度、语义补全、执行门控、反馈话术、异常兜底”五层，而不是只做一个语音输入框。这样能把小爱实习里的拒识优化经验，迁移到具身智能任务执行场景。

State Machine

语音任务状态机

每个状态都对应一个用户风险和一个产品策略。

Listening收音中，风险是噪声和截断；策略是显示听取状态。
Review识别结果进入确认区，用户可以修改后执行。
Understanding解析意图、对象、目标位置和约束。
Clarifying对象或位置不明确时询问，不直接执行。
Confirming药品、重物、老人相关任务进入安全确认。
Executing执行过程中允许暂停、改目标、换对象和接管。
Recovering路径被挡、目标移动等异常触发重规划或人工接管。

短回复与误识别策略

短回复不是普通聊天，而是上下文补槽。比如系统问“红色杯子还是蓝色杯子”，用户说“红色的”，系统应把它绑定到上一轮候选集，而不是当成新任务。

红色的 = 候选补槽 对 = 确认执行 不是这个 = 换对象 取消 = 停止任务

Metrics

语音交互指标

这些指标可以放进作品集，证明你有产品质量意识。

指标 衡量什么 为什么对具身智能重要
误触发率 用户没有明确下达任务时，系统是否错误执行。 物理动作有真实成本，误执行比聊天误答更危险。
澄清触发准确率 对象/位置歧义时是否发起澄清。 避免错拿、错送、错放，是家庭机器人信任基础。
确认成本 高风险任务确认次数与用户打断率。 确认太少不安全，确认太多会让用户不用。
短回复解析率 “红色的”“对”“不是这个”等短句是否正确接上上下文。 真实语音交互天然短、碎、依赖上下文。
恢复成功率 路径受阻、目标移动、用户改口后能否重规划。 执行期协作能力决定 Agent 是否能进入物理世界。
